# Подключение аккаунтов к локальному «Кадру»

Код подготовлен. До настройки проекта реальные письма и облачная коллекция не работают; гостевые подборки остаются доступны.

## 1. Создать проект

Открой https://supabase.com/dashboard и создай аккаунт, организацию и бесплатный проект. Пароль базы сохрани у себя: приложению он не нужен. Дождись готовности проекта.

## 2. Подключить настройки

В окне Connect или в Settings → API / API Keys найди Project URL и Publishable key (допускается старый ключ anon).

Открой `.env.local` рядом с `server.cjs` и заполни:

```env
SUPABASE_URL=https://идентификатор.supabase.co
SUPABASE_PUBLISHABLE_KEY=публичный_ключ
```

TMDB_READ_TOKEN оставь на месте. Не используй service_role, secret key или пароль базы. Файл настроек исключён из Git и не раздаётся сервером.

## 3. Создать таблицу

Открой SQL Editor проекта, вставь содержимое `supabase/schema.sql` и выполни. Скрипт создаёт таблицу user_items и политику: пользователь читает и изменяет только собственные записи. Повторный запуск не удаляет коллекцию.

## 4. Настроить код в письме

В Authentication → Email Templates → Magic Link замени шаблон письма на текст с кодом:

```html
<h2>Вход в Кадр</h2>
<p>Твой код для входа: <strong>{{ .Token }}</strong></p>
<p>Если ты не запрашивал вход, проигнорируй письмо.</p>
```

Включи провайдер Email в Authentication → Sign In / Providers. Настрой длину и срок действия email OTP по желанию; интерфейс принимает код от 6 до 10 цифр. Приложение проверяет код, а не ссылку из письма.

## 5. Доставка писем

Встроенный отправитель Supabase ограничен и предназначен для тестов. Без собственного SMTP письма разрешены только адресам участников команды проекта. Для других пользователей подключи SMTP в Authentication → Email → SMTP Settings. Потребуются настройки почтового провайдера, обычно подтверждённый домен отправителя. Они задаются в Supabase, а не в исходниках приложения.

Документация:
- https://supabase.com/docs/guides/auth/auth-email-passwordless
- https://supabase.com/docs/guides/auth/auth-smtp

## 6. Запуск и проверка

Перезапусти `node server.cjs`. Открой приложение через прежний адрес в браузере. Нажми «Войти», введи свою почту и полученный код. После входа можно отдельно перенести гостевую коллекцию.

Проверь: вход на компьютере и телефоне в один аккаунт, добавление и снятие фильма, оценки и поправки настроения, обновление страницы, выход, затем вход под другим аккаунтом. На втором аккаунте чужая коллекция появляться не должна. Эти проверки с настоящими аккаунтами ещё обязательны после настройки.

В локальной HTTP-версии сессия передаётся HttpOnly-cookie с SameSite=Strict. Токены находятся только на сервере, файл .auth-sessions зашифрован ключом .auth-key. Оба файла исключены из Git. Не размещай этот локальный сервер открыто в интернете: перед публикацией нужны HTTPS, NODE_ENV=production, проверка SMTP, доступности Supabase и конфигурации хостинга.

Синхронизация сохраняет изменения по отдельным карточкам. При одновременной правке одной карточки действует последнее сохранение. Код не создаёт Supabase-проект и не выполняет SQL автоматически.
